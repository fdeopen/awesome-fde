# 公开案例的收录与维护

首页保持最多 30 条精选公开案例，详细阅读笔记集中在 [selected.md](selected.md)。[原始阅读索引](catalog.md)继续保存其他文章，不将全部阅读资料都计为企业案例。

## 本批来源

从 FDE中国项目 `fde-china/src/content/generated/cases-external/` 保存的公开文章正文中，结合现有 119 条来源索引逐篇筛选。此次收录 30 条，覆盖制造业与汽车、电商与零售、金融与保险、医疗健康、物流与供应链、互联网与媒体、专业服务 7 类。

原文链接与来源日期来自 `cases/catalog.json`；编辑后的标题、行业、阅读重点及简要拆解保存在 `cases/selected.json`。每条记录附来源文件相对路径与 SHA-256，不包含本机绝对路径或文章全文。

## 选择标准

- 有可阅读的公开来源，正文能够支持具体业务问题与实施做法。
- 优先选择企业实践、工程过程与失败复盘；纯新闻、概念介绍、产品发布和未经实施的方案不进入精选。
- 本地自建项目、模拟教学、只有标题或登录提示的资料不进入本选集。
- 按业务所在行业归类，RAG、客服、知识管理、Agent 等作为阅读主题，不与行业混用。
- 一篇多企业经验汇总计一条；同一企业的不同工作流分别说明任务，不把重复转载计为新案例。
- 只整理来源能够支持的事实。效果指标、建设目标和未来规划分别理解；学习建议写入“FDE 启发”。

例如，`FC-096` 的本地正文只有登录提示，未纳入本批；通用电商案例归入“电商与零售”，不因技术相同而自动归为跨境案例。

## 更新流程

1. 核对公开文章正文与来源，必要时先在 `catalog.json` 增加新的稳定 ID、链接和日期。
2. 修改 `selected.json` 中对应条目。替换案例时保持首页不超过 30 条；完整文章索引仍可继续增长。
3. 填写中文和英文短标题、阅读重点，以及业务问题、实施做法、资料范围和 FDE 启发。按实际来源更新 `snapshot` 的文件路径与 SHA-256，并更新整理日期。
4. 在仓库根目录运行生成与检查命令：

```bash
python3 scripts/render.py
python3 scripts/render.py --check
python3 scripts/check_docs.py
```

生成器同步更新中文首页、英文首页、案例首页与详细阅读笔记，并检查重复 ID、重复来源、分类、必填字段和来源记录。GitHub Actions 会检查生成结果是否与数据一致。

新增公开来源优先链接原始发布者；社区整理页需保留来源线索。按[贡献指南](../CONTRIBUTING.md)提交修改，可用[案例模板](case-template.md)补充更完整的公开实践资料。
