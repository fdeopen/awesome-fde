# Agent 工程师路线

适合具备 Python 或 TypeScript、API、数据库和基础后端开发能力，希望构建可生产化 Agent/Workflow 的工程师。

## 毕业目标

交付一个有状态、可追踪、可评估、可回退并支持人工介入的 Agent 系统，而不是只在理想输入下工作的演示。

## 学习顺序

| 阶段 | 学习重点 | 实践产物 |
| --- | --- | --- |
| 1. 确定性工作流 | 状态机、分支、重试、幂等、超时 | 显式状态图与失败路径 |
| 2. 工具调用 | Schema、授权、最小权限、审批 | Tool Registry 与权限矩阵 |
| 3. 上下文与记忆 | 会话状态、业务状态、短期/长期记忆 | 状态模型与保留策略 |
| 4. RAG | 解析、检索、重排、权限过滤、引用 | 可回归的检索链路 |
| 5. 评估与 Trace | 任务、流程、系统、风险、业务五层评估 | Golden Dataset 与 Trace |
| 6. 生产运行 | 网关、限流、降级、告警、人工接管 | 灰度发布和回退演练 |

## 架构原则

- 能用确定性代码解决的步骤，不交给模型自由规划。
- 读操作与写操作分级，执行型工具默认需要更严格审批。
- 业务状态与聊天记录分离，关键动作使用稳定 ID 串联。
- 每次模型、Prompt、知识源、工具或权限变更都触发相应复测。
- 失败样本进入回归集，同时保留新分布样本，避免只在旧错题上优化。

## 毕业检查

- [ ] 任务状态、终止条件和异常路径显式可见
- [ ] 工具输入输出有 Schema、权限、超时和幂等设计
- [ ] 高风险动作有审批、回滚和人工接管
- [ ] 评估覆盖正确性、流程、系统、风险和业务结果
- [ ] Trace 能重建一次关键决策链
- [ ] 有限流、熔断、成本预算和降级方案
