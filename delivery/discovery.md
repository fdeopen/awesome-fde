# 发现与场景诊断

发现阶段的目标不是收集“想做一个 Agent”的愿望，而是找到高价值、高频、可测量、具备数据条件且有人负责的工作流。

## 输入

- 项目背景、发起人、预算与时间窗口
- 战略层、运营层和一线用户访谈
- 当前流程、系统、数据、权限和例外
- 历史任务样本、工作量、质量与成本基线
- 已知风险、替代方案和停止条件

## 工作方法

1. 观察真实工作，不从模型或供应商开始讨论。
2. 画出触发、参与者、步骤、等待、返工、决策、系统和异常。
3. 对候选场景从价值、可行性、风险和学习速度四个方向判断。
4. 明确业务负责人、技术负责人、数据负责人和风险接受人。
5. 将模糊愿望写成一页 [机会卡](../templates/discovery/opportunity-card.md)。

## 就绪度检查

| 维度 | 应有证据 |
| --- | --- |
| 业务问题 | 流程、真实样本、量化基线、责任人 |
| 用户与采用 | 用户群、任务频率、主管和推广机制 |
| 数据 | 来源、授权、质量、更新、保留与删除 |
| 集成 | 接口、身份、网络、测试环境和变更窗口 |
| 评估 | 真实任务集、判定规则和当前基线 |
| 风险 | 权限、日志、回退、人工接管和风险登记 |
| 经济性 | 成本树、价值树和关键敏感性假设 |
| 复用 | 相邻场景、可复用假设和平台责任人 |

任何不可逆高风险且没有人工接管的场景都应暂停。分数只能辅助讨论，不能替代业务、技术和治理共同决策。

## 阶段产物

- [业务访谈提纲](../templates/discovery/interview-guide.md)
- 当前流程与问题地图
- 机会卡与场景优先级
- 数据、系统、权限与风险清单
- 业务基线、价值假设和停止条件
- 初版 RACI

## 退出条件

只有在用户、任务、基线、数据、责任与风险边界均可说明时，才进入方案与 PoC。否则应缩小场景、先补前提或停止。
