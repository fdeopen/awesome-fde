# 实施与集成

实施阶段把已验证方案变成可维护的生产候选系统，并持续保留“为什么这样决定”的证据。

## 工作流

1. 建立 [项目计划](../templates/implementation/project-plan.md)，明确里程碑、责任、依赖和门禁。
2. 先跑通端到端最小链路，再逐步优化性能与体验。
3. 对接身份、数据、知识、业务 API、审批和人工队列。
4. 建立自动测试、离线评估、Trace、成本和风险检测。
5. 按周演示真实任务与失败样本，及时管理范围和预期。
6. 完成灰度、回退、故障和人工接管演练。

## 版本登记

每个可发布版本至少记录：

- 代码、配置、依赖和镜像
- 模型、参数、Prompt 与 Guardrail
- 知识源、解析、切分、Embedding、索引和权限规则
- 工具 Schema、连接器、服务账号和授权策略
- 评估集、评分规则、阈值与已知失败类型
- 数据库迁移、特性开关、部署环境和回滚版本

## 变更分级

| 风险 | 示例 | 最低复测与批准 |
| --- | --- | --- |
| 低 | 文案、非行为配置、监控展示 | 冒烟测试；技术负责人记录 |
| 中 | Prompt、排序、知识源、模型小版本 | 回归、成本、延迟与风险抽样；FDE + 业务批准 |
| 高 | 新模型、工具、权限、自主性、敏感数据、外部用户 | 全量离线评估、红队、影子运行、回退演练；业务 + 技术 + 治理批准 |

## 完成标准

- 测试环境使用已授权数据，生产凭据不进入个人设备或仓库。
- 关键路径、失败路径、重试、超时、幂等和回滚均被验证。
- Trace 可以关联用户、请求、模型/Prompt/知识/工具版本和业务结果。
- 文档、运行手册、培训材料和所有权随系统一起交付。
