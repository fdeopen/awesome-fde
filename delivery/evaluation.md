# 评估体系

企业 AI 评估要回答的不是“答案像不像”，而是“工作是否在可接受风险与成本下完成”。

## 五层评估

| 层级 | 典型指标 | 样本与方法 |
| --- | --- | --- |
| 任务 | 正确、完整、引用、分类、抽取、行动结果 | 专家金标准、规则和经校准的模型评分 |
| 流程 | 步骤、工具选择、审批、终止与人工升级 | 场景脚本、状态断言和故障注入 |
| 系统 | 延迟、可用性、容量、恢复、成本 | 压测、混沌测试、SLO 与成本追踪 |
| 风险 | 注入、越权、泄露、误导、偏差、不可审计 | 红队、权限测试和高风险样本 |
| 业务 | 周期、吞吐、返工、质量、收入、成本、采用 | 基线、对照、时间序列和财务复核 |

## 评估阶段

```text
离线任务 → 沙箱仿真 → 影子运行 → 有限生产 → 稳态运营
```

每一步都要有进入阈值、负责人、证据和不通过动作。离线通过只代表质量门的一部分，不能替代权限、运营和业务验收。

## 数据集治理

- 评估集版本化并记录来源、授权、分布和标注规则。
- 高频、长尾、高风险、对抗和无答案样本都要覆盖。
- 评估数据、生产数据与训练/优化数据明确隔离。
- 新失败样本加入回归集，同时持续补充新的随机或时间切片样本。
- 记录人工一致性、Judge 偏差、阈值变更和例外批准。

## 成本口径

同时报告：

1. 每次请求成本
2. 每个完成任务成本
3. 每个合格业务结果成本

只有第三种口径能与人工流程或原系统做同口径比较。
