# 方案设计

方案设计把业务命题转化为可运行、可评估、可治理的最小闭环。

## 先做架构取舍

| 任务特征 | 优先选择 |
| --- | --- |
| 规则明确、结果确定、风险高 | 传统代码或规则引擎 |
| 需要基于企业知识回答并引用 | RAG |
| 步骤稳定、分支可枚举 | Workflow / 状态机 |
| 步骤难以预先穷举，需要动态选择工具 | Agent，但限制自主性 |
| 高风险决策或动作 | 人机协同，保留审批和接管 |

## 方案至少覆盖

1. **业务闭环**：用户、触发、输入、决策、动作、输出、反馈。
2. **系统边界**：哪些能力由模型、规则、人工和现有系统负责。
3. **数据流**：来源、分类、处理、存储、保留、删除和跨境。
4. **模型与上下文**：模型、Prompt、知识源、检索与版本策略。
5. **工具与权限**：工具 Schema、最小权限、审批、幂等和回滚。
6. **质量体系**：任务集、阈值、错误分类和复测机制。
7. **运行体系**：SLO、Trace、告警、容量、成本和灾备。
8. **退出体系**：替代方案、数据导出删除、供应商与模型切换。

## 阶段退出问题

- 方案能否在当前数据、权限和组织约束下运行？
- 最关键的不确定性是否被明确，而不是被隐藏在“大模型能力会提升”中？
- 失败能否被发现、隔离、升级和恢复？
- 业务、技术、数据、治理和运营是否接受各自责任？
