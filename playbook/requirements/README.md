# 2. 需求调研

## 阶段目标

把模糊诉求写成可检验需求。

## 输入与输出

- 输入：访谈记录、角色清单与流程图。
- 输出：需求表、As-Is/To-Be与RACI。
- 交接：编制人提交证据版本，业务与技术责任人记录接受、补充或停止决定。

## 工作方法

分别访谈主管和操作人员；将冲突需求绑定具体任务并记录取舍。

1. 确认输入的来源、时间与适用范围。
2. 执行上述方法，用稳定ID关联任务、结果与证据。
3. 对关键结论做一次反例检查，再交给下一阶段接收人。

## 常见问题与控制

只听管理者描述会遗漏异常路径；抽样观察异常任务。需求变更记录版本、影响与批准人。

输出有明确所有者、版本、证据和下一步；无法支持结论的假设标记为待验证。继续到 [3. 场景识别与优先级](../scenario-design/README.md)。
