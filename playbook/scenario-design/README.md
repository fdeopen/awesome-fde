# 3. 场景识别与优先级

## 阶段目标

选择可在当前资源内验证的场景。

## 输入与输出

- 输入：需求、基线、数据条件与预算。
- 输出：场景评分、优先级与排除项。
- 交接：编制人提交证据版本，业务与技术责任人记录接受、补充或停止决定。

## 工作方法

用价值、可行性、采用、可控性打分；先处理阻断项，再按依赖排序。

1. 确认输入的来源、时间与适用范围。
2. 执行上述方法，用稳定ID关联任务、结果与证据。
3. 对关键结论做一次反例检查，再交给下一阶段接收人。

## 常见问题与控制

平均高分不代表数据就绪；硬性前提单独判断。为暂缓项目定义重启条件。

输出有明确所有者、版本、证据和下一步；无法支持结论的假设标记为待验证。继续到 [4. 业务对象与本体建模](../ontology-modeling/README.md)。
