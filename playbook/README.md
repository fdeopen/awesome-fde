# FDE Playbook · 企业AI交付方法

12个阶段形成从业务理解到价值与产品化的闭环。阶段可迭代，但不能跳过输入证据与接收责任。一个阶段结束时，下一阶段负责人应能复现关键结论。

| 阶段 | 目标 | 输出 |
| --- | --- | --- |
| [1. 业务发现](business-discovery/README.md) | 找到值得解决且有人负责的业务问题 | 机会卡与基线 |
| [2. 需求调研](requirements/README.md) | 把模糊诉求写成可检验需求 | 需求表、As-Is/To-Be与RACI |
| [3. 场景识别与优先级](scenario-design/README.md) | 选择可在当前资源内验证的场景 | 场景评分、优先级与排除项 |
| [4. 业务对象与本体建模](ontology-modeling/README.md) | 建立跨系统一致的对象、关系和动作语义 | 对象字典、关系图、动作权限表 |
| [5. 数据治理与系统盘点](data-governance/README.md) | 确认数据可用、可追溯且可持续更新 | 数据资产表、质量报告与接口约定 |
| [6. 技术方案设计](solution-design/README.md) | 形成满足约束的最小可运行闭环 | ADR、系统卡、风险清单与报价边界 |
| [7. PoC原型验证](poc-delivery/README.md) | 证伪最可能阻断项目的假设 | PoC报告、逐题结果与继续/停止决定 |
| [8. 工程实施与系统集成](implementation/README.md) | 将PoC转成可维护的生产候选 | 集成版本、回归集、运维草案 |
| [9. 评测与业务验收](evaluation/README.md) | 用代表性证据决定交付是否成立 | 验收报告、Bad Case与剩余限制 |
| [10. 生产部署与持续运营](production-delivery/README.md) | 让系统可恢复、可值守、可持续改进 | 发布记录、SLO、运行手册与月度复盘 |
| [11. ROI评估与项目复盘](business-value/README.md) | 确认实际采用与可兑现价值 | ROI情景表、归因限制与下一阶段决策 |
| [12. 资产沉淀与产品化](productization/README.md) | 把可重复能力交给明确的产品所有者 | 资产目录、维护责任与第二次复用报告 |
